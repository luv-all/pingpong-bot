# 라켓 헤드·리니어 레일 2단계 제어

## 목적

현재 실기 제어는 발사기 반복 시험용 `3cm 감긴 준비 → 검출 후 높이 정렬 → 임팩트`를
실행한다. 카메라가 예측한 공의 x·y·z에 라켓 중심을 맞추고, 타격 순간 라켓이
상대편 탁구대 끝선 중앙을 바라보게 한다.

## 입력

추정기는 다음 정보를 제어 워커에 보낸다.

```text
CommitRequest {
    track_seq,
    trajectory: BallTrajectory,
    stage: Provisional | Refined,
    at,
}
```

`track_seq`는 공이 바뀌었음을 명시한다. 새 번호를 받으면 이전 공의 단계 상태를
버리므로, 이전 공이 정밀 단계까지 도달하지 못해도 다음 공을 정상 처리한다.

## 단계 판정

1. EKF가 위치와 속도를 추정하고 목표를 선택하면 `Provisional`이다.
2. 첫 정상 3D 관측 후 0.25초 이상 지나고, 최근 목표 세 개가 최신 목표에서
   10cm 이내이면 `Refined`다.

예측 공분산은 화면 진단에는 표시하지만 제어 시작 게이트로 사용하지 않는다.

## 출력

| 단계 | 리니어 레일 | 수평 조준 ID 3 | 다른 관절 |
|---|---|---|---|
| 준비 | 중앙 레일 | 상대편 방향 | 1.05m 높이에서 임팩트 반대 방향으로 3cm 감기 |
| `Provisional` | 라켓 헤드 x가 공 x와 같아지도록 이동 | 상대편 끝선 중앙 조준 | 3cm 감김을 유지하며 예측 높이 정렬 |
| `Refined` | 갱신된 공 x로 다시 이동 | 같은 조준 함수 적용 | 아직 타격 전이면 최신 목표 사용 |
| 임팩트 | 목표 레일 유지 | 공→상대편 끝선 중앙 방향 | 예측 공 위치까지 펴기 |

조준각은 다음 단일 함수로만 계산한다.

```text
aim(rail_x) = atan2(table_center_x - rail_x, opponent_end_y - rail_mount_y)
```

이 각을 논리 관절 1(기본 Dynamixel 배열의 ID 3)에 적용한 FK로 헤드 x
오프셋을 구하고, 오프셋만큼 레일을 보정한다. 최종 임팩트는 전체 자세 IK로
공 위치와 라켓 방향을 함께 맞추되 현재 준비 자세와 가까운 해를 선택한다.
레일 목표는 물리 범위 `0.000~1.410m`로 제한한다. 현재 포즈에서
레일 가속·최고속도와 조준축 최고속도를 적용해 최소 필요 시간을 먼저 계산한다.
공 도착까지 남은 시간이 그보다 짧으면 명령을 보내지 않는다. 명령 시간은
기본적으로 `0.05~0.30초`이며, 남은 시간이 0.05초보다 짧으면 그 남은 시간,
실제 최소 이동 시간이 0.30초보다 길면 그 최소 이동 시간을 쓴다. 어떤 경우에도
레일 정렬과 감긴 자세의 높이 보정은 병렬로 진행하며 둘 다 공 도착 전 완료 가능해야 한다.

공 검출 직후 최소 0.12초부터 한계를 만족하는 가장 짧은 높이 정렬 시간을 찾는다.
라켓은 임팩트 자세 기준 총 3cm 뒤로 감긴 뒤, 남은 비행시간을 전진 궤적에 사용해
공 도착 시 최대 출력 시험용 목표 속도 1.80m/s를 만든다. 필요한 관절 속도는 실기
모델 상한으로 제한한다. 전진 임팩트용 고정 최소시간은 미리 예약하지 않고, 백스윙이
끝난 뒤 공 도착까지 실제로 남은 시간을 그대로 사용한다. 0.06초 팔로스루 후 감긴
중앙 준비 자세로 복귀한다. 이 값과 플래너는 실기와 GUI sim이 공유한다.

## 명령 후 실측 오차

실기 제어 워커는 예상 도착 시점부터 20ms 간격으로 레일 엔코더와 조준 ID 3을
다시 읽는다. 두 축이 허용 오차 안에 두 번 연속 들어와야 `converged`로 인정한다.
예상 도착 후 500ms까지 수렴하지 않으면 `timeout`이다.

```text
rail_commanded_m
rail_measured_m
rail_commanded_minus_measured_m
aim_commanded_rad
aim_measured_rad
aim_commanded_minus_measured_rad
```

명령 시점에는 `requested`(제어기 요청)와 `applied`(하드웨어 clamp·틱 양자화 후
실제 전송)도 따로 남긴다. 오차는 `applied - measured`로 계산한다.
메인 스레드의 `Commanded` 이벤트에도 요청값이 아니라 실제 적용값이 들어간다.

레일 절대 오차가 20mm, 조준축 절대 오차가 3°를 넘으면 `WARN`, 그 안이면
`INFO`로 기록한다. 이전 명령이 수렴하기 전에 정밀 명령이 나가면 직전 포즈를
`superseded`로 남기고 새 명령을 시작한다. `timeout`이 3회 연속 나면 레일을 정지하고
조준축을 현재 위치에 홀드한 뒤 제어 워커를 종료한다. 정상 수렴하면 연속 timeout
횟수는 0으로 돌아가며, `superseded`는 timeout으로 세지 않는다.

> **주의 (2026-08-05):** 위 수렴·타임아웃·3회 연속 중단 경로는 현재 실기
> 루프에서 도달 불가하다(`pending_verification`이 채워지지 않음). 문서는
> 의도한 설계를 기록한 것이고, 부활 여부는 별도 결정 사항으로 남아 있다.

## 실기·시뮬레이션 공통 경계

`DirectController`가 목표 선택, 헤드 x 보정, 레일 범위 제한, 조준각, 명령 시간을
한 번만 계산한다. 실기 워커와 GUI 시뮬레이션은 모두 이 `DirectControlCommand`를
받는다. 실기는 `Hardware::command_rail_and_racket`으로 실제 장치에 보내고,
관절 전용 궤적은 레일 이동을 덮어쓰지 않고 동시에 실행한다. GUI 시뮬레이션도
같은 명령의 레일·조준 목표와 관절 전용 궤적을 `robot::State`에 병렬 적용한다.
별도의 generic pipeline에서 쓰는 `SimHardware`도 같은 `Hardware` 경계를 구현한다.
임팩트 팔로스루가 끝나면 실기와 GUI sim 모두 `Planner::ready_prewind`로
중앙 1.05m 높이의 3cm 감긴 준비 자세에 복귀한다.

한 공의 임팩트 계획이 시간·관절·테이블 한계 때문에 실패하면 제어 워커 전체를
끝내지 않는다. 그 `track_seq`만 완료 처리해 반복 계획을 막고 다음 공을 계속 받는다.

## 현재 제외한 기능

- 공별 반환 탄도를 맞추는 적응형 라켓 속도 계산
- 스윙 커밋·포기 상태 머신

반환 탄도를 역산하는 전체 스윙 플래너는 비활성이며, 발사기 시험용 백스윙과
높이·방향 정렬 임팩트만 실행한다.
