## 1. 결론 요약

**허용치를 완화하지 않는다. 값은 0.005를 유지한다.**

출발 가설("5 mm는 라켓 반너비의 6.7%뿐이라 면 안에 들어오는 좋은 후보를 대량
기각하고 있고, 그게 낮은 커밋률의 원인 중 하나다")은 **데이터로 반증됐다.**

- 이 게이트가 기각한 후보는 허용치 ≥ 5e-4에서 **0개**다.
- 허용치 **5e-5 ~ 0.055 m 구간(1100배 범위)이 완전히 동일한 결과**를 낸다 —
  커밋 집합, eval 점수, 실제 Rapier 접촉 좌표까지 비트 단위로 같다.
- 커밋 못 한 샷은 전부 후보가 이 검사에 **도달조차 못 했다**(IK/토크/기구학
  한계에서 먼저 탈락). 즉 완화해도 살아나는 샷이 원리적으로 없다.

값이 "느슨해도 안전한가"가 아니라 **"애초에 발동하지 않는다"**가 핵심이다.
사용자의 기하학적 직관(5 mm ≪ 라켓 반너비)은 맞지만, 그 사실이 커밋률
저하의 원인으로 이어지지는 않는다.

---

## 2. 왜 발동하지 않는가 — 해석적 증명

게이트는 후보 궤적의 FK 종단 포즈에서 접촉점을 재계산한다:

```
contact = face_center + n · (BALL_RADIUS + RACKET_HALF_Z)
```

그런데 `face_center`와 `n`은 방금 `solve_impact_target`이 **예측 임팩트
위치를 목표로** 푼 IK 해에서 나온다. `inverse_pose_with_rail`의 수렴 판정
기준은(`src/robot/mod.rs`, 함수 내부 private const):

| 상수 | 값 |
|---|---|
| `POSITION_TOLERANCE` | `2e-4` m |
| `NORMAL_TOLERANCE` | `1e-3` (법선 벡터 차의 노름) |

따라서 접촉 오차에는 구조적 상한이 있다:

```
|e| ≤ |Δface_center| + |Δn|·(R + HALF_Z)
    ≤ 2e-4 + 1e-3 × (0.02 + 0.005)
    = 2e-4 + 2.5e-5
    = 2.25e-4 m = 0.225 mm
```

**실측 최대 접촉 오차는 0.00017 m (0.17 mm)** — 이 해석적 상한 0.225 mm
바로 아래다. 두 방법이 독립적으로 같은 결론에 도달한다.

즉 `MAX_CONTACT_ERROR = 0.005`는 **해석적 상한의 22배**이며, IK 자체가
깨지지 않는 한 정상 후보를 기각할 수 없다. 이 상수는 후보를 걸러내는
**필터가 아니라, IK/FK 계약 위반을 잡는 tripwire**다.

### 허용 구간은 양쪽에서 막혀 있다

| 경계 | 공식 | 값 |
|---|---|---|
| **하한** (정상 IK 해를 기각하지 않을 조건) | `POSITION_TOLERANCE + NORMAL_TOLERANCE·(R + HALF_Z)` | `2.25e-4` m |
| **상한** (접촉이 라켓 면 안에 남을 조건) | `min(RACKET_HALF_X, RACKET_HALF_Y) − BALL_RADIUS` | `0.055` m |

현재 값 0.005는 하한의 **22배**, 상한의 **1/11** — 244배 폭의 허용 구간
안쪽에 여유롭게 들어있다. 계획서 §4가 예시로 든 "라켓 반너비 최솟값 − 공
반지름" 공식은 위 표의 **상한**에 해당하고, 실제로 그 값(0.055)까지 올려도
측정 결과는 변하지 않는다 — 다만 올릴 이유가 없다(§5).

## 4. 접촉 유효성 검증 (핵심 안전 검사)

"허용치를 풀면 실제 접촉이 라켓 면 밖으로 밀려나지 않는가"가 이 WP의
수용 기준이었다. 결과:

- **커밋된 스윙의 실제 접촉은 사실상 면 중심이다.** `|face_x| ≤ 0.0005 m`,
  `|face_y| ≤ 0.0035 m`, 면내 여유 ≈ **0.0745 m**. 공 전체가 면에 올라오려면
  0.020 m만 있으면 되므로 **3.7배 여유**다.
- `on_face`는 모든 허용치에서 eval 20/20, random 11/12로 **불변**이다.
- 면 밖 접촉(여유 −0.0096 m)은 **단 하나**, random 격자의
  `lat-0.50_yaw+15.0` 샷이고 14개 허용치 전부에서 `commit=false`다 —
  아무것도 커밋하지 않는 1e-7 대조군에서도 값이 비트 동일하다. 즉
  **스윙하지 않는(coarse 추종 자세) 라켓에 공이 스친 우발 접촉**이며
  허용치와 무관하다.

**결론**: 완화가 유효하지 않은 접촉을 만들지는 않는다. 그러나 얻는 것도
없다.

## 5. 그래서 왜 유지하는가

완화의 기대이익이 **측정상 정확히 0**인 반면, 비용은 tripwire 감도다.

- 0.005에서는 향후 변경(예: WP2b 랭킹 변경, WP4a elbow-up 단일 config,
  IK 허용오차 완화, 손으로 만든 타겟)이 IK 품질을 떨어뜨려 20 mm짜리 접촉
  오차를 만들면 **잡힌다**.
- 0.055에서는 그게 조용히 통과한다. 공이 면에서 벗어나 "빗맞는" 것까지는
  아니어도, 면 중심에서 밀려난 접촉은 유효 반발·법선 방향이 달라져 약한
  리턴이 된다 — 지금 이 프로젝트가 이미 싸우고 있는 증상이다.

tripwire는 좁을수록 유용하고, 좁게 두는 비용이 0으로 측정됐다. 따라서
**값을 유지하고, 대신 값의 근거를 코드에 남긴다.**

### 실제 변경 내용

`plan_best_swing` 함수 안의 지역 `const`를 모듈 수준 `pub const`로 올리고
위 §2의 양방향 경계 유도와 실측 근거를 doc comment로 붙였다. **숫자와
비교식은 그대로이므로 동작은 비트 단위로 동일하다** — 마법 숫자가 근거를
가진 상수가 된 것뿐이다.

## 6. 재현 절차

스윕에 쓴 계측 훅은 **의도적으로 커밋하지 않았다** — 플래너 프로덕션
경로에 가변 전역(thread-local override)을 남기지 않기 위해서다. 재현하려면
아래 패치를 임시로 적용한다.

`src/planner/swing/physics.rs`의 `plan_best_swing`에서:

```rust
// 1) 지역 상수를 훅으로 교체
let max_contact_error: f64 = wp2c_probe::tolerance();

// 2) 접촉 검사에 계측 추가
let contact_error = (contact - prediction.impact_position.coords).norm();
if contact_error > max_contact_error {
    wp2c_probe::note_candidate(contact_error, false);
    continue;
}
wp2c_probe::note_candidate(contact_error, true);
```

그리고 같은 파일에 thread-local 훅 모듈을 추가한다 (`TOLERANCE`,
`ACCEPTED`, `MIN_SEEN`, `REJECTED` 4개 `Cell` + `set_tolerance` /
`reset_shot` / `note_candidate` / `accepted_error` / `min_seen_error` /
`rejected_count`). 진단 하네스는 매 샷 `reset_shot()`을 부르고, 커밋
시점에 `accepted_error()`를, 첫 Rapier 접촉 시점에 라켓 로컬 좌표를
기록한다:

```rust
let iso = world.arm_bodies.ee_world_isometry(&world.rigid_body_set).unwrap();
let local = iso.inverse_transform_point(&ball_center_point);
// local.x / local.y = 면내 좌표 (half = 0.075 / 0.08), local +Z = 면 법선
```

실행:

```bash
git worktree add /tmp/wp2c-tol <phase0-commit>
cd /tmp/wp2c-tol   # 위 패치 적용
CARGO_TARGET_DIR=/tmp/wp2c-target \
  WP2C_TOLS="0.0000001,0.00002,0.00005,0.0001,0.00015,0.0002,0.00025,0.0005,0.001,0.005,0.01,0.02,0.04,0.055" \
  WP2C_GRID=both \
  cargo test --release --test diag_contact_tolerance -- --ignored --nocapture
```

770런 소요 시간 약 9분 30초(릴리즈, M-series, 다른 워크트리와 CPU 경합
상태). 원본 로그: 측정 당시 `/tmp/wp2c-sweep.txt`.

## 7. 부수 발견 (이 WP 범위 밖 — 후속 과제 후보)

스윕 격자 전수 데이터에서 이 WP와 무관하게 드러난 두 가지. **둘 다 허용치와
전혀 무관하며**(14개 값 전부에서 동일), 별도 과제로 다뤄야 한다.

1. **eval Right 존 10샷이 전멸한다.** Left 10/10 커밋, Center 10/10 커밋인데
   **Right 0/10 커밋 · 0/10 접촉 · 0점**이다. `min_seen_error = inf`이므로
   후보가 접촉 검사에 도달하지 못했다 — IK/기구학 한계에서 탈락한다.
   좌우 비대칭이 이 정도로 크다는 건 레일 도달 범위·마운트 기하 또는
   `RailMotion` 실현성 판정의 비대칭을 시사한다(WP5가 지적한 "플래너가
   레일 가속을 안 본다"와 교차 가능). **WP1/WP2a/WP3에 넘길 항목.**
2. **커밋된 20샷이 전부 1점이다** (접촉은 하지만 네트를 못 넘김).
   eval 점수 20점 = 20접촉 × 1점. 이건 RC-1/RC-4(약한 리턴) 계열 증상이고
   접촉점 허용치와 무관하다. WP2b(임팩트 세기 랭킹)·WP7(downscale 감사)의
   대상.
