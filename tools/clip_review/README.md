# clip-review

**예측 궤적이 실제 궤적으로 수렴하는가** — 클립을 0.1x로 돌려 눈으로 본다.

창 셋이 같은 프레임을 동시에 보여준다:

| 창 | 내용 |
| --- | --- |
| `cam0` / `cam1` | OpenCV — 원본 프레임 + 두 궤적을 **재투영**해 겹침 |
| `clip-review sim` | kiss3d `SimScene` 자식 프로세스 — 테이블 위에 두 궤적을 그대로 |

sim 창은 `tools/verify_stereo`와 같은 방식이다 — kiss3d와 OpenCV highgui가 둘 다 메인
스레드를 요구해서, 부모가 자기 자신을 `--sim-child`로 띄우고 한 줄 JSON으로 먹인다.
sim 창이 안 떠도 카메라 창만으로 계속 간다 (관전용이다).

색은 세 창에서 같다:

| 색 | 뜻 |
| --- | --- |
| **초록 선 (굵게)** | 실제 궤적, **현재 프레임까지** — 검출 + 삼각측량 (`Triangulate::pixels`, 재투영 14 px 게이트) |
| **죽인 초록 (얇게)** | 실제 궤적, **아직 안 온 구간** — 아래 참조 |
| **회색 선** | 매 프레임 다시 굴린 예측 (`live`) |
| **자홍 선 (굵게)** | **커밋 순간에 얼린 예측** — 이게 "예측이 맞았나"의 대상 |
| **노란 동그라미** | 검출 픽셀 (카메라 창) |
| **흰 동그라미** | EKF 추정 위치를 그 카메라로 재투영 |
| **주황 공** | EKF 추정 위치 (sim 창) |
| **반투명 공** | 이 프레임의 삼각측량 점 (sim 창) |

흰색·하늘색은 밝은 실내 영상과 밝은 테이블 위에서 죽는다. 채도 높은 **초록 ↔ 자홍** 보색을
쓰고, 카메라 창의 모든 선은 검은 밑선을 한 겹 깔고 그 위에 그린다.

## 어디까지 그리나

**로봇 마운트(`defaults::rail_frame().mount_y()` = −0.10 m)까지만** 그린다. 그 뒤는 로봇이
이미 지나친 자리라 볼 이유가 없고, 길게 그려 두면 화면만 어지럽다. 경계를 지나는 선분은
정확히 그 지점에서 끊는다.

예측 자체는 여전히 플레이 부피를 벗어날 때까지 적분한다 — 평면 통과·`MISS` 계산에 필요하다.
**그리기만** 자른다.

## 미래 궤적이 왜 미리 보이나

**캐싱이다.** 재생이 시작되기 전에 클립을 한 번 통째로 훑어 검출·삼각측량·EKF 재생을
끝내 두므로, 실제 궤적은 **처음부터 끝까지 이미 안다**. 커밋 예측이 이후로 어디로 갔는지와
나란히 보려면 미래가 있어야 해서 일부러 그린다.

다만 과거와 같은 굵기로 그리면 "지금 아는 것"과 구분이 안 되므로, 현재 프레임을 기준으로
**굵은 초록(지금까지) / 얇고 죽인 초록(아직 안 온 구간)**으로 나눈다.

## 왜 예측이 두 개인가

**매 프레임 다시 굴린 예측(어두운 선)은 실제에 붙어 보이는 게 정상이다.** 언제나 현재
공 위치에서 출발하니까. 공이 갈수록 남은 구간이 짧아지고, 결국 실제에 먹힌다. 그걸로는
"예측이 맞았나"를 판정할 수 없다.

판정 대상은 **커밋 예측(밝은 선)**이다. 실기 파이프라인은 [`estimator::decide`](../../src/estimator/decision.rs)가
`Attempt`를 낸 프레임에 `CommitRequest`를 보내고, 제어 워커가 궤적을 짜고 나면 스윙이
끝날 때까지 `Recovering`이라 새 요청을 안 받는다 — **한 샷에 실질적으로 한 번**이다.
이 툴은 같은 게이트를 그대로 태워서 그 첫 `Attempt`의 예측을 **얼려 둔다**. 이후 프레임에서
그 선은 바뀌지 않으므로, 실제와 벌어진 만큼이 그대로 오차다.

게이트는 순서대로 `NoTrack → NoPrediction → BeforeMidcourt → OutOfWindow → Uncertain`이고,
HUD `gate` 줄에 지금 어디서 막혀 있는지가 나온다.

> 게이트는 원래 `src/real/`(바이너리)에 있었는데 라이브러리로 옮겼다 — 툴이 실기와 다른
> 게이트를 쓰면 여기서 보이는 커밋 시점이 실기와 달라져 진단이 거짓말을 한다.

## 왜 카메라 창이 본론인가

sim 창은 감을 주지만, **틀린 이유**는 카메라 창에서 갈린다. 흰 선과 하늘색 선이 벌어졌을 때
그 프레임의 초록 동그라미가 공 위에 있으면 검출은 맞은 것이고 물리·필터가 틀린 것이다.
초록이 엉뚱한 데(바닥에 떨어진 공, 사람 팔) 있으면 검출이 틀린 것이다. 이 구분이 안 되면
어디를 고쳐야 할지 정할 수 없다.

## 사용

```bash
cargo run --release -p clip-review -- --clip fly_04
cargo run --release -p clip-review -- --clip fly_02 --speed 0.05
cargo run --release -p clip-review -- --clip fly_08 --start 200
```

시작할 때 클립을 한 번 훑어 검출·삼각측량·EKF 재생을 **미리 다 끝낸다**. 그래서
되감아도 값이 다시 계산되지 않는다 — 같은 프레임을 몇 번을 다시 봐도 숫자가 같다.

## 프리롤은 1배속

클립 대부분은 공이 아직 발사되지 않은 프리롤이다 (fly_04는 589프레임 중 첫 삼각측량이
한참 뒤). **첫 공이 잡히기 전까지는 1배속**으로 지나가고, 거기서부터 `--speed`가 걸린다.
HUD에 `1.00x (preroll)`로 표시된다.

## 키

| 키 | 동작 |
| --- | --- |
| `Space` | 일시정지 / 재개 |
| `←` `→` 또는 `,` `.` | 한 프레임 (일시정지로 들어감) |
| `[` `]` | 10프레임 |
| `0` | 처음으로 |
| `q` / `ESC` | 종료 |

클립 끝에 닿아도 **자동 종료하지 않는다** — 마지막 프레임에서 멈춰 서고, 거기서 되감을 수
있다. 종료는 `q`/`ESC`뿐이다.

## 옵션

| 옵션 | 기본 | 설명 |
| ------ | ------ | ------ |
| `--clip NAME\|DIR` | **필수** | `data/clips/<name>` |
| `--speed` | `0.1` | 재생 배속. 0.1 = 10배 느리게. 프리롤 구간에는 안 걸린다 |
| `--scale` | `0.5` | 카메라 창 축소 배율 |
| `--start` | `0` | 시작 프레임 |

## 화면 vs 콘솔

**화면에는 두 줄만 남긴다** — 프레임/시각/배속과 그 카메라의 검출 여부. 숫자를 화면에
쌓으면 정작 봐야 할 궤적을 가린다.

나머지는 **콘솔**로 간다. 추적 중인 프레임마다 한 줄씩, 같은 프레임은 두 번 안 찍는다
(프리롤은 볼 게 없으니 조용하다). 스크롤해서 앞뒤 프레임을 비교할 수 있는 게 장점이다.

```
frame  t     | cam0 cam1 | 3d x y z reproj | ekf x y z |v| sigma_p sigma_v | gate si | live +.1/+.2/+.3s [cm]
f402   t= 5.461 | 812,340 455,318 | 3d +0.62 +1.41 +0.94 rp2.1 | ekf +0.62 +1.40 +0.94 |v|5.4 sp2.1 sv45 | ATTEMPT si12 | live 3/8/--
```

| 칸 | 뜻 |
|---|---|
| `cam0 cam1` | 각 카메라 검출 픽셀. `----`는 못 찾음 |
| `3d … rp` | 삼각측량 좌표와 재투영 오차 [px] |
| `ekf … sp sv` | 필터 상태와 위치·속도 불확실성 [cm], [cm/s] |
| `gate si` | 실기와 같은 커밋 게이트 판정 + `impact_sigma` [cm] |
| `live` | 매 프레임 예측이 +0.1/+0.2/+0.3초 뒤를 얼마나 맞히나 [cm] |

`--`는 오차 0이 아니라 **못 쟀다**는 뜻이다 (그 시각에 짝이 되는 삼각측량이 없음).

## 결론은 COMMIT 요약

pass 1이 끝나자마자 한 번 찍는다. **이 툴의 답이다.**

```
COMMIT  frame 402 t=5.461s  tti 0.28s  sigma 12cm
  target  x+0.70 y+0.20 z+0.95
  at y=0.08  pred x+1.42 z+0.88 |v|5.1   real x+0.31 z+0.91   MISS 111.2cm
```

`MISS`가 실기가 하드웨어에 넘겼을 예측과 실제가 어긋난 거리다. 커밋이 끝내 안 나면
`COMMIT never`와 마지막 게이트 판정을 찍는다 — 그것도 결과다.

## 삼각측량 짝 맞추기

프레임 **인덱스**로 맞춘다. 두 AVI는 동시 녹화라 같은 인덱스가 같은 시각이고, 여기는
"실제로 어디였나"를 만드는 자리라 런타임의 타임스탬프 보간보다 인덱스가 정확하다
(`diag_clip_prediction`과 같은 규칙).
