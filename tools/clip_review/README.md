# clip-review

**예측 궤적이 실제 궤적으로 수렴하는가** — 클립을 0.1x로 돌려 눈으로 본다.

창 셋이 같은 프레임을 동시에 보여준다:

| 창 | 내용 |
| --- | --- |
| `cam0` / `cam1` | OpenCV — 원본 프레임 + 두 궤적을 **재투영**해 겹침 |
| `clip-review sim` | kiss3d `SimScene` 자식 프로세스 — 테이블 위에 두 궤적을 그대로 |

sim 창은 `tools/verify_stereo`와 같은 방식이다 — kiss3d와 OpenCV highgui가 둘 다 메인
스레드를 요구해서, 부모가 자기 자신을 `--sim-child`로 띄우고 한 줄 JSON으로 먹인다.
sim 창이 안 떠도 카메라 창만으로 계속 간다 (관전용이다).

색은 세 창에서 같다:

| 색 | 뜻 |
| --- | --- |
| **흰 선** | 실제 궤적 — 검출 + 삼각측량 (`Triangulate::pixels`, 재투영 14 px 게이트) |
| **하늘색 선** | 예측 궤적 — 그 프레임 EKF 상태에서 `Kinematics::step`으로 굴린 것 |
| **초록 동그라미** | 검출 픽셀 (카메라 창) |
| **자홍 동그라미** | EKF 추정 위치를 그 카메라로 재투영 |
| **주황 공** | EKF 추정 위치 (sim 창) |
| **반투명 공** | 이 프레임의 삼각측량 점 (sim 창) |

## 왜 카메라 창이 본론인가

sim 창은 감을 주지만, **틀린 이유**는 카메라 창에서 갈린다. 흰 선과 하늘색 선이 벌어졌을 때
그 프레임의 초록 동그라미가 공 위에 있으면 검출은 맞은 것이고 물리·필터가 틀린 것이다.
초록이 엉뚱한 데(바닥에 떨어진 공, 사람 팔) 있으면 검출이 틀린 것이다. 이 구분이 안 되면
어디를 고쳐야 할지 정할 수 없다.

## 사용

```bash
cargo run --release -p clip-review -- --clip fly_04
cargo run --release -p clip-review -- --clip fly_02 --speed 0.05
cargo run --release -p clip-review -- --clip fly_08 --start 200
```

시작할 때 클립을 한 번 훑어 검출·삼각측량·EKF 재생을 **미리 다 끝낸다**. 그래서
되감아도 값이 다시 계산되지 않는다 — 같은 프레임을 몇 번을 다시 봐도 숫자가 같다.

## 프리롤은 1배속

클립 대부분은 공이 아직 발사되지 않은 프리롤이다 (fly_04는 589프레임 중 첫 삼각측량이
한참 뒤). **첫 공이 잡히기 전까지는 1배속**으로 지나가고, 거기서부터 `--speed`가 걸린다.
HUD에 `1.00x (preroll)`로 표시된다.

## 키

| 키 | 동작 |
| --- | --- |
| `Space` | 일시정지 / 재개 |
| `←` `→` 또는 `,` `.` | 한 프레임 (일시정지로 들어감) |
| `[` `]` | 10프레임 |
| `0` | 처음으로 |
| `q` / `ESC` | 종료 |

## 옵션

| 옵션 | 기본 | 설명 |
| ------ | ------ | ------ |
| `--clip NAME\|DIR` | **필수** | `data/clips/<name>` |
| `--speed` | `0.1` | 재생 배속. 0.1 = 10배 느리게. 프리롤 구간에는 안 걸린다 |
| `--scale` | `0.5` | 카메라 창 축소 배율 |
| `--start` | `0` | 시작 프레임 |

## HUD

HUD는 카메라 창에 있다 (sim 창은 그림만). `detect` 픽셀과 `3d` 좌표는 그 카메라 것이고,
나머지 줄은 **두 창에 똑같이** 붙는다 — 어느 쪽을 보고 있든 같은 숫자가 보이게.

`converge`가 본론이다. 리드타임 +0.1/+0.2/+0.3초 뒤의 **예측**과 그때
**실제로** 지난 곳의 거리다. `--`는 오차 0이 아니라 **못 쟀다**는 뜻(그 시각에 짝이 되는
삼각측량이 없음). `hit`은 접수 평면 통과 상태 — 제어측이 실제로 받을 위치와 속도.

## 삼각측량 짝 맞추기

프레임 **인덱스**로 맞춘다. 두 AVI는 동시 녹화라 같은 인덱스가 같은 시각이고, 여기는
"실제로 어디였나"를 만드는 자리라 런타임의 타임스탬프 보간보다 인덱스가 정확하다
(`diag_clip_prediction`과 같은 규칙).
