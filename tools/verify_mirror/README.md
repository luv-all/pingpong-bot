# verify-mirror

듀얼 MX-64 미러 페어(ID1↔ID2)가 `듀얼 MX-64 정렬 불일치` 에러로 구동을 막을 때,
카메라·레일·제어 워커 없이 **그 두 모터만** 열어 실측/기대 tick 차이를 반복 측정하는
독립 진단 도구. `verify-stereo`와 같은 위치(`tools/`)의 별도 바이너리다.

## 왜 필요한가

`--mode real`은 시작할 때 미러 정렬을 한 번 검사하고, ±40tick(≈3.5°)을 넘으면 즉시
에러로 죽는다 (`src/hardware/dynamixel/dynamixel_bus.rs::verify_mirror_alignment`).
그 에러 로그는 숫자 하나(그 순간의 자세)만 보여줄 뿐, 자세를 바꿔가며 오차가 어떻게
움직이는지는 보여주지 않는다 — 그런데 오차가 조립 오프셋 상수(`mirror_slave_offset_ticks`)
문제인지 백래시/헐거운 혼 같은 기계적 문제인지는 **여러 자세에서 비교해야만** 구분된다.

이 도구는 대상 모터의 토크를 꺼서 손으로 돌려볼 수 있게 하고, Enter를 누를 때마다
다시 측정해 사람이 읽을 수 있는 진단을 계속 출력한다.

## 사용

```bash
cargo run -p verify-mirror
# 포트가 기본값(COM8)과 다르면
cargo run -p verify-mirror -- --dxl-port COM5
```

1. 대상 ID와 위험(토크 OFF 시 처질 수 있음) 경고가 뜬다. `y` + Enter로 진행.
2. 매 측정마다 다음을 출력한다:
   - master/slave 실측 tick·각도
   - 현재 오프셋 상수 기준 기대값
   - 오차(tick·각도)와 허용범위 대비 상태(정상/불일치)
   - "ID{slave}를 X → Y로 옮기세요" 형태의 구체적 지시
   - 오차가 자세마다 크게 바뀌면 기계적 문제부터, 항상 비슷하면 오프셋 상수
     재보정을 하라는 판단 기준
3. `q` + Enter로 종료. **종료해도 대상 ID의 토크는 OFF로 남는다** — 정상 구동은
   `--mode real`로 다시 시작하거나 전원을 재순환해야 한다.

## 주의

- 이 도구는 정렬 검사 자체를 우회한다 (`DynamixelBus::open`만 호출하고
  `verify_mirror_alignment`를 부르지 않는다) — 진단 목적이므로 정상 런타임 경로가 아니다.
- 대상 관절이 순수 요(yaw) 회전이 아니라 중력을 버티는 관절이라면, 토크를 끄는 순간
  처질 수 있다. 손으로 받칠 준비를 하고 진행할 것.
